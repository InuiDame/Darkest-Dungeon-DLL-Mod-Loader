# Lua 按 C++ 编译，并给源码打补丁

Lua 5.4.9 的本地包按 C++ 编译：`lua_error` 变成 C++ 异常，从 DDLua 的 C++ 函数、计数 hook 里抛错时，中间栈帧的析构照常运行。`xmake/lua.lua` 在安装包时按唯一的锚点改源码，锚点找不到或不唯一就构建失败，版本号是 `dd_patch`（和 `lddstep.h` 里的 `LUA_DDPATCH` 对齐）。DDLua 直接用 Lua C API，不用 sol2 的封装：沙箱、预算、保护调用都要逐个控制谁会抛错、谁会调用 Mod 的元方法。

补丁分四类：

- **进度回调**：库函数里由 Lua 数据决定次数的循环（模式匹配、`string.rep`、`table.concat`/`sort`/`insert`/`move`、`string.pack`、`utf8`、字符串转数字、`math.min/max` 等）按工作量计步，超时时报预算错误。没有 `lua_State` 的内核操作（长串比较、长串哈希）在操作之后检查，对正在运行的线程设 hook，下一条指令报错；正在运行的线程由 `lua_resume`、`lua_closethread` 进出时通知 DDLua。
- **表的哈希**：整数、浮点、指针键用带密钥的哈希（进程密钥混入表的地址），扩容时直接插入、不先查找，Mod 构造不出冲突键，有冲突也是线性的；字符串哈希的种子用系统随机数。
- **弱键表**：只有弱键、没有弱值的表（ephemeron）按强引用表处理，`'kv'`、`'v'` 照常。ephemeron 链能让 GC 的原子阶段变成平方级，又不经过任何检查点。按强引用处理只会让对象多活，内存仍受上限约束，每次进存档 VM 也会重建（[ADR 0021](0021-lua-vm-per-campaign.md)）。
- **其他**：`string.rep` 结果为空串时直接返回；`luaE_resetthread` 恢复 `allowhook`；紧急 GC 和原子阶段的通知（DDLua 给这类整段停顿计时，补到当前入口的截止时间上）、下一轮 GC 的阈值交给 DDLua（压到内存上限以下，大堆也走增量 GC）；`LUA_IDSIZE` 改为 160。

补丁对语义的影响用 Lua 官方测试集核对，按设计的差异和结果见 `docs/03-lua-system.md` 的「沙箱和稳定性」。

## 考虑过的方案

- 按 C 编译：`longjmp` 越过 C++ 栈帧时跳过析构。
- 换别的实现（Luau 等）：和 [ADR 0012](0012-lua54-sol2.md) 的选型冲突，迁移成本远大于补丁。
- 给字符串函数限制输入长度：伤正常用法，合法长度内的 n·m 查找照样能卡住。
- 看门狗线程：打断不了正在运行的 C 循环。
- 限制 `convergeephemerons` 的轮数以保留弱键语义：要改 GC 的标记逻辑，出错就是提前回收可达对象。

## 后果

升级 Lua 版本时要重新确认每个锚点和补丁的语义，并重跑官方测试集。弱键表的语义和标准 Lua 不同，写在 03 和 `sdk/lua/sandbox.lua` 里。
