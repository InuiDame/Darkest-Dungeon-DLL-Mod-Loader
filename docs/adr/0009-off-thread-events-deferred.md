# 非主线程的原生事件复制后排队到主线程

读档、进地牢、城镇访问的加载线程会派发原生事件（如 `InventoryAddItemEvent`、`RaidStartEvent`）。事件中枢在派发线程上按字段复制一份，排队到主线程再交给订阅者。这类负载带 `DD_EVENT_F_DEFERRED`，只读、不能取消，指针字段恒为 NULL。

这样所有回调（包括 Lua）都在主线程运行，订阅表、Lua VM 都不用加锁，也不会在加载线程上碰到还在构建的对象。

## 考虑过的方案

在原线程上直接派发、给订阅表和 VM 加锁：Lua 不是线程安全的，而且回调拿到的指针指向正在加载的对象，不采用。

## 后果

延迟事件比游戏动作晚到，拿不到对象指针。需要对象状态的订阅者等对应的主线程事件（如 `campaign.load`、`raid.step`）再去读。
