# dd.fs 只写本 Mod 的数据目录

`dd.fs.write`、`dd.fs.remove` 只作用于 `<游戏根目录>\DDModLoader\data\<mod id>\`；读接口加 `{ root = "data" }` 选这个目录，默认仍是只读的 Mod 目录。数据目录不分存档，分存档的状态用 `dd.store`（[ADR 0031](0031-persist-sidecar-content-hash.md)）。

- 路径规则同只读接口：拒绝 `..`、绝对路径、盘符、冒号、通配符、Windows 保留的设备名；父目录逐级创建，每一级取最终路径和根目录比较，联接、符号链接逃不出去；写入的路径最多 8 层。
- 原子写入：同目录的临时文件、`FlushFileBuffers`，再 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`，失败时原文件不变。
- 上限：每个 Mod 的总大小 `data_max_mb`、条目数 `data_max_files`（文件和目录都算），本会话第一次写之前扫描一次用量；`dd.fs.remove` 能删空目录。
- 预算：每次调用按文件操作次数和数据量计入执行预算，返回前检查截止时间。
- Mod id 只差大小写的两个 Mod 都不加载（NTFS 上是同一个数据目录、同一个旁路文件）。

## 考虑过的方案

- 写 Mod 目录：Workshop 的目录归 Steam 管，更新时会被覆盖或删掉。
- 分存档的数据目录：和 `dd.store` 重复，而 `dd.store` 还有一致性核对。
- 路径不限层数：每一级父目录都要打开、取最终路径，400 层时一次写入 219 毫秒，循环里能卡几十秒（审核 C-B2）；扫描有深度上限时，更深的文件还能绕过配额（C-Y1）。

## 后果

- 数据目录跨存档共享，Mod id 应当全局唯一。
- 每次写入同步刷盘，机械硬盘上一次可能几十毫秒；单次写入超出预算时只能写完再报超时，不要每帧写。
