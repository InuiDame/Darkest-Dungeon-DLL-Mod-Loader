# P3 审核发现索引

P3（Lua 运行时）经过三轮对抗审核和一轮核对审核，代码注释和测试用例里的编号（如「审核 A-A1」「R2B-备注4」）指的是这里的条目。原始报告和修复记录是 P3 的工作文件，验收后已删除，这里只留编号、问题和处理结果。设计上的结论见 ADR 0019–0024。

编号规则：第一轮写成「报告-条目」（报告 A、B、C 三份，条目号沿用各报告），第二、三轮写成 `R2A-阻断1`（第二轮报告 A 的阻断第 1 条），核对审核写成「核对审核应修 1」。

## 第一轮

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| A-A1（阻断） | 模式匹配里有不计步的路径，一次 `string.match` 卡住主线程两分钟 | 补丁给 `match()`、字符集、`%b`、回引用等计步 |
| A-B1 | `load` 的 reader 分段喂入时，词法分析在两次检查之间跑几秒 | 分块交给语法分析，每块之前检查 |
| A-B2 | 每帧总时间没有上限 | 调度器的工作设 `frame_budget_ms`，顺延并轮转；事件回调写进 03 的「不保证」 |
| A-B3 | `dd.import` 返回提供方的原表 | 只读浅代理，按（使用方、提供方）缓存；共享对象写进 03 |
| A-C1 | 硬链接能读到 Mod 目录外的文件 | 只写文档：硬链接只能本机创建 |
| A-C2 | `math.random` 的状态整个 VM 共享 | 每个 Mod 一份 |
| A-C3 | `lua_smoke` 没覆盖按 C++ 编译后的析构 | 加用例 |
| A-C4 | `print`、`warn` 先拼接再截断，没有限流 | 边拼接边截断，按 Mod 限速 |
| A-C5 | `data-and-mods.md` 漏了一条不复制启用列表的路径 | 补上 |
| A-C6 | 预算没覆盖的单次 C 调用 | 写进 03 |
| B-B1（阻断） | 怪物 guid 每场战斗重新计数，旧句柄会解析到下一场的怪物 | DDCore 维护战斗序号放进句柄（ADR 0024） |
| B-Y1 | 超出 float 范围的有限值写回游戏变成 ±inf | DDCore 按字段宽度检查，`DD_EV_E_RANGE` |
| B-Y2 | 整数写入被静默截断成 int32 | 同上 |
| B-Y3 | 回调里出原生异常后 VM 还被继续使用 | VM 标记为损坏，停止派发、丢弃 |
| B-Y4 | `combat.md` 里 `+0x768`、`+0x790` 的说法和 [运行] 标记不对 | 改正为最大生命的属性值结构和掩码 |
| B-N1 | 手动恢复调度器的协程，语义容易误解 | 每帧清理已结束的任务；03 写明不要手动恢复 |
| B-N2 | `actor_from_pointer` 读虚表 | 没有问题（SEH 保护，Lua 传不进任意地址） |
| B-N3 | 重载不重新解析 manifest | 写进 03 |
| B-N4 | 撤销不检查归属 | 检查当前代表哪个 Mod 执行 |
| B-N5 | `2A6D4BB` 的写入点不全 | 列全 |
| B-N6 | 浮点 filter 是精确比较 | 写进 03 |
| C-B1（阻断） | `p3d_core` 的 `isolation` 用累计次数比本场次数，误报失败 | 每场记基线 |
| C-S1 | 第 7 项的对照是可选的，场景方案也做不出它的口径 | 改成必需的第二次运行（lua 方案、存档 B） |
| C-S2 | 重建 0 个 Mod 也判通过 | 要求同样的 Mod 加载成功并开始工作 |
| C-S3 | 不核对日志是不是同一次运行 | 运行标识、开始时间、部署时间、序号 |
| C-S4 | 不检查 DDLua 是不是默认配置 | 检查配置行；`deploy` 备份不是 rig 生成的 `DDLua.cfg` |
| C-S5 | 「游戏不卡死」不看打断用时 | 超过预算加 500 毫秒判失败 |
| C-S6 | 漏勾测试 Mod 判失败 | 判「没有触发」 |
| C-S7 | `verify-real` 只核两个文件，`deploy` 不查联接 | 检查联接，扩大核对范围 |
| C 备注 1–11 | 探针格式漂移时放过、`damage.halve` 的受伤倍率、强杀写存档、`scope.raid` 的流程、`topic_dump` 的逗号等 | 全部修了，空目录（备注 8）无害不改 |
| C 无法确认 1 | 阵亡、解雇的英雄是否移出名册 | 查清：阵亡留在名册，解雇立即删除（`combat.md`），检查排除这两类 |

## 第二轮

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| R2A-阻断1 | `gsub` 替换串（`add_s`）不计步 | 计步，并排查 `lstrlib`、`ltablib`、`lutf8lib`、`lstring` 等全部同类循环 |
| R2A-阻断2 | 弱键表的 ephemeron 链让 GC 原子阶段变成平方级 | 只有弱键的表按强引用处理（ADR 0019） |
| R2A-阻断3 | `main.lua` 的语法分析不在预算入口里 | 读取、语法分析、执行共用一个入口 |
| R2A-应修1 | 错误信息和失败原因不截断、不限速 | 截断，计入按 Mod 的限速，`log_max_mb` 总量 |
| R2A-应修2 | `dd.once` 回调出原生异常时没有撤销通知 | 事件跳板的 SEH 过滤器先标记损坏 |
| R2A-备注1、3、4、5 | 代理挡不住类写法、拆除的 `<close>` 没有总时间、`load` 块太大、位置捕获计步为负 | 文档写明共享；`teardown_budget_ms`；块改成 4 KB；按 1 计 |
| R2B-阻断1 | `rig.py` 不检查测试目录本身，被重定向时会写、删真实安装 | 每个会写或删的命令先检查测试目录本身 |
| R2B-应修1 | `battles` 可以只凭没加载 `p3c_actor` 的存档判通过 | 要求同一次进入里五项句柄检查都跑到 |
| R2B-应修2 | `wait_event` 快照只盯第一个英雄 | 任何挨打的英雄都可以 |
| R2B-备注1 | `Battle::Create` 内部置 `bs_create` 之前的窗口 | 「没有战斗」之后怪物表不空也算新战斗 |
| R2B-备注2–7 | 不派发 `battle.start` 的开战路径、地址、受伤倍率、`verify-real` 的缺口、流程顺序 | 写进 `combat.md`、03 和场景文档，脚本相应修改 |

## 第三轮

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| R3A-阻断1 | 整数键哈希冲突让扩容变成平方级 | 带密钥的表哈希，扩容直接插入（ADR 0019） |
| R3A-阻断2 | `l_str2int` 扫空白和十六进制数字不计步 | 计步 |
| R3A-阻断3 | 没有 `lua_State` 的进度回调在协程里不起作用 | `lua_resume`、`lua_closethread` 进出时通知正在运行的线程 |
| R3A-应修1 | 内存到上限时每次分配失败都做完整的紧急 GC | 一个入口最多一次没起作用的，之后冷却 1 秒 |
| R3A-应修2 | `math.min/max`、含 `\0` 的串比较和查找不计步 | 计步，字符串比较改成 `memcmp` |
| R3A-备注1–3 | 检查放在操作之前、挂起协程拉长 GC、DDCore 的装卸日志 | 操作之后检查并在入口末尾判定；03 补数据；装卸日志限速 |
| R3B-阻断1（降为应修） | `.rig.json` 的路径不校验，覆盖写入跟随链接 | 只接受测试目录内、某个方案会部署的相对路径；先断开链接再写 |
| R3B-备注1–4 | `run` 不查子目录、`verify-real` 抛异常、倍率样本跨战斗、`combat.md` 的地址 | 全部修了 |
